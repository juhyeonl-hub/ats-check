# ADR-001: 공고를 스크래핑하지 않는다

- 상태: **채택됨**
- 날짜: 2026-08-15

## 맥락

`ats-check`는 채용 공고를 읽고 판정한다. 공고를 얻는 가장 편한 방법은
LinkedIn·Indeed 같은 구직 사이트에서 자동으로 긁어오는 것이다.
"URL만 주면 알아서 판정"이 가장 매끄러운 사용자 경험이기도 하다.

## 결정

**스크래핑을 구현하지 않는다.** 공고 본문은 사용자가 붙여넣는다.

## 근거

### 1. 이용약관 위반이다

LinkedIn·Indeed의 ToS는 자동 수집을 금지한다. 위반 시 **구직 계정이 정지될 수 있다.**
이 도구의 사용자는 구직자다. 구직 도구를 쓰다가 구직 계정을 잃는 것은
제품이 해결하려는 문제보다 큰 피해를 만든다.

### 2. 포트폴리오로 공개할 수 없다

이 프로젝트의 목적 중 하나는 공개 포트폴리오다.
ToS를 위반하는 코드가 들어 있으면 **레포를 공개하는 것 자체가 리스크**가 된다.
채용 담당자가 보는 코드에 스크래퍼가 있으면 감점 요인이다.

### 3. 깨지기 쉽다

구직 사이트의 HTML 구조는 자주 바뀌고, 봇 차단은 계속 강해진다.
스크래퍼는 유지보수 부채이며, **핵심 가치(판정 로직)와 무관한 곳에서 시간을 소모**한다.
3주 일정에서 이 부채를 질 여유가 없다.

### 4. 핵심 가치가 아니다

이 도구의 가치는 "공고를 가져오는 것"이 아니라 "공고를 거르는 것"이다.
복사-붙여넣기는 2초면 된다. 그 2초를 없애려고 위 세 가지 위험을 지는 것은
비용-이득이 맞지 않는다.

## 결과

- 입력은 파일, stdin, 클립보드로 제한한다
- `--url` 옵션은 **URL을 메타데이터로 저장만** 하고 접근하지 않는다 (`save --url`)
- v0.1은 네트워크 호출이 0이다. 이것이 §1의 차별점("로컬에서만 처리")을 뒷받침한다

## 대안: 공식 API (v0.2)

수집이 필요하다면 스크래핑이 아니라 **공개 API**를 쓴다.

- TE-palvelut (핀란드 고용경제부) 공공 구인 API
- Duunitori·Oikotie 등의 RSS 피드

이는 `ats-check fetch`라는 **별도 서브커맨드로 분리**한다.
`fetch`는 외부 의존이라 깨질 수 있고, `check`는 순수 로컬이라 깨지지 않는다.
둘을 섞으면 외부 API 장애가 도구 전체를 무용지물로 만든다.
